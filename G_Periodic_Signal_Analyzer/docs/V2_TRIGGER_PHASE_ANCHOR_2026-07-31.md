# V2.0时域触发与相位锚分析

日期：2026-07-31
发布版本：`v2.0.0`

## 结论

V2.0任务书描述的刷新后水平漂移，主因位于相位折叠结果与显示之间：

```text
每帧DMA起点相位不同
→ 相位折叠固定phase_cycles=0
→ 256槽波形形状基本相同但发生循环旋转
→ 794点显示忠实画出不同的循环起点
```

3秒刷新周期只决定多久看见一次跳动；淘晶驰水平反向补偿只改变发送顺序，二者
都不是根因。最小修复应只给256槽周期波形确定显示起点，不改ADC、FFT、Vpp、
RMS、频率、频谱或纵向幅值。

## 已实现模式

| HMI帧 | 模式 | 行为 |
|---|---|---|
| `A5 02 07 00 5A` | 无触发 | 保留旧的帧起点，用作对照 |
| `A5 02 07 01 5A` | 上升过零 | 主正峰之前的稳定上升过零，默认 |
| `A5 02 07 02 5A` | 下降过零 | 主正峰之后的稳定下降过零 |
| `A5 02 07 03 5A` | 正峰值 | 周期主正峰 |

上升/下降过零使用线性插值得到亚槽交越位置，并要求交越前后越过
`max(0.5 mV, 2% Vpp)`滞回带。正峰值使用相邻三点抛物线细化。含谐波波形
可能有多个过零点，因此两种过零模式都以主正峰为参照选择相邻交越，避免仅按
数组首点搜索导致半周期或局部毛刺间跳变。

HMI下拉框应在弹起且`down==0`时，通过`prints cb0.val,1`直接发送最终模式，
不使用四条按钮命令或单个按钮循环状态。运行状态切换模式时只重画时域曲线；
停止状态只保存模式。固件和HMI的默认值都设为上升过零（`mode/val=1`）。

## 当前验证

- Keil ArmClang 6.7全量重建：`0 Error(s), 0 Warning(s)`。
- 构建体积：`Code=64652, RO-data=59000, RW-data=52, ZI-data=50756`。
- `ADC.hex`长度：`348008 bytes`。
- SHA-256：`AB2505B9D3C280B243558176C1FCDC615E741C6AF7462095026A390F9CEDEC10`。
- 用户已确认将上述HEX烧录到实机；本轮没有新的CubeProgrammer输出或运行截图，
  因此“已烧录”不能替代下面的真实ADC运行验收。
- 20个不同整体起始相位的合成复合波形离线验证：

| 模式 | 1T最大帧间RMSE | 3T最大帧间RMSE |
|---|---:|---:|
| 无触发 | 142.89983 mV | 142.89983 mV |
| 上升过零 | 0.00633 mV | 0.00633 mV |
| 下降过零 | 0.00641 mV | 0.00641 mV |
| 正峰值 | 0.00767 mV | 0.00767 mV |

该离线测试只证明循环相位锚算法能消除合成帧的整体旋转，不证明真实ADC中的
频率误差、低相位覆盖、毛刺或伪峰已经解决。

## 已烧录但尚未完成的实机证据

V2.0任务书要求的以下项目仍需补齐，当前不能标记为已验证：

1. 真实ADC连续至少20帧的槽位、像素和相位位移；
2. 2秒、3秒、5秒刷新间隔对比；
3. 上升/下降过零在纯正弦和非对称复合波形中的稳定性；
4. 正峰值在多局部峰波形中的确定性；
5. 切换触发后Upp、Urms、频率和频谱完全不变；
6. 淘晶驰实物上1T/3T方向与FE/FD链路回归。

当前推荐继续保留3秒刷新作为基线。只有实机证据表明首次结果响应不满足题目
2秒要求时，才单独调整刷新状态机；刷新周期不能替代相位锚修复。
