# 队友4096-2代码链与实现思路

本文只整理代码事实和实现边界，供后续网页端撰写说明材料；不代写竞赛报告正文，
也不替队友修改暂未定型的`Vpp_Robust()`。

## 1. 一帧数据怎样产生

```text
TIM3中心对齐PWM / CH4
→ ADC1在CH4上升沿采PA0
→ ADC2在CH4下降沿采PA1
→ DMA1 Channel 1/2各得到2048点
→ 两路完成回调令AdcConvEnd累计到2
→ 停TIM3
→ adc_b[i]、adc_b1[i]交错并换算为VO[4096]
→ FFT、频谱/Vpp/RMS、显示桥接
→ 重新启动两路DMA和TIM3
```

交错顺序由`main.c`明确规定：

```c
VO[2 * i]     = adc_b[i]  * 3.3f / 4096.0f;  /* ADC1先采 */
VO[2 * i + 1] = adc_b1[i] * 3.3f / 4096.0f;  /* ADC2后采 */
```

因此当前算法和显示的共同输入是已经带伏特单位的`VO[4096]`，等效采样率约
`2048193 Hz`。PA0、PA1必须接收同一个模拟信号；若两路增益、偏置或相位延迟
不同，交错序列会产生奇偶点纹波，数字算法不能自动消除这种硬件失配。

## 2. 频谱主链

1. 把`VO[i]`写入复数FFT输入的实部，虚部置零。
2. 使用`arm_cfft_sR_f32_len4096`完成4096点复数FFT。
3. 使用`arm_cmplx_mag_f32()`得到幅值，后续只搜索前1024个正频率bin。
4. `4096-2`先按bin区间对`output[]`除以11档经验增益，再开始找峰；这取代了
   旧版在找到每个峰后调用`beishu(f)`的做法。
5. 每次取最大峰，并把中心前后各4个bin的幅值平方求和，按
   `2*sqrt(sum)/4096`换算该分量峰值；已计入的9个bin清零后继续找下一峰。
6. 最多得到`F/V`、`FB/VB`、`FC/VC`三组频率和峰值幅度，`sof()`按频率升序
   重排。
7. 第三峰幅度过小或不满足当前谐波判定时，`flag=2`；否则`flag=3`。

当前频率换算使用`2048000/4096=500 Hz/bin`的近似口径；Goertzel和桥接使用
`2048193 Hz`。这两个数只差约0.0094%，但最终频率标定时仍应统一为实测采样率。

## 3. 幅值与RMS链

`Vpp_Robust(VO, 4096)`复制并插入排序全部4096点，然后平均排序后
`240..259`与对称高端20点之差，作为当前`Upp`。这是队友现有方案，当前只记录，
不建议在本轮交接中替换；其精度、复杂度和最终保留与否由后续实测决定。

`Vpp_R()`会按基频选取整数周期长度、把尾部置零、从`VO`减去直流量，再对有效
长度调用`arm_rms_f32()`。要特别注意：这个函数会原地改写`VO`。

代码还计算了三次`goertzel_sync()`，但结果`r/rB/rC`目前没有进入显示或最终
判断。写材料时可以说明它是保留的同步检波实验量，不能描述成已经参与最终结果。

## 4. 显示桥接为什么分两步

桥接必须读取原始、未被`Vpp_R()`改写的`VO[4096]`来完成频率细化、相位折叠、
Huber和谐波模型，因此调用顺序固定为：

```c
AnalyzerBridge_PrepareReal(
    VO, 4096, ANALYZER_SAMPLE_RATE_HZ,
    spectrum_flag,
    spectrum_frequencies_hz,
    spectrum_amplitudes_v);

float Vrms = Vpp_R();
AnalyzerBridge_PublishPreparedReal(vpp, Vrms);
```

`PrepareReal()`同步消费VO，但不发布不完整结果；`PublishPreparedReal()`只补入队友
算出的Vpp和RMS，再原子提交一帧。桥接不缓存第二份4096点真实VO，也不再次做
ADC码值换算，从而避免16 KB额外RAM和单位重复换算。

## 5. 显示侧怎样使用

桥接发布统一`AnalyzerResult`，显示模块只读取这一份快照：

- `vpp_mv`、`rms_mv`显示Upp和Urms；
- 最多三个频谱分量显示频率与`mVpk`；
- 4096点VO经相位折叠形成256点时域显示快照；
- 普通/Huber只影响时域显示副本，不反向修改队友FFT、Upp和Urms；
- KEY1短按切换1T/3T，本地主线长按进入测试；给队友的生产包保持长按刷新。

## 6. 写说明材料时可直接使用的结论

| 可写内容 | 边界 |
|---|---|
| 双ADC在同一TIM3通道的相反边沿采样，软件交错为4096点 | 必须同时说明两路接同一信号并需要校准失配 |
| 4096点FFT约500 Hz/bin | 当前精确采样率与FFT近似常量尚待统一标定 |
| 分段频响补偿在找峰前统一作用于频谱 | 11档系数是现有经验参数，不能写成已完成全量仪器标定 |
| 九bin能量合并降低单bin泄漏影响 | 仍需窗函数、边界和邻近谱线实测证据 |
| 两阶段桥接保证VO改写前完成波形提取 | 这是确定的软件时序边界 |
| 静态工作区避免1 KB主栈溢出 | 不等于RAM无限，新增4096点数组仍需看map |

网页端在形成正式文字前还应补齐：同一输入下的信号源设置、PA0/PA1波形、
两路原始ADC、`VO[4096]`、屏幕Upp/Urms/频率、运行时间与误差表。没有这些同步
证据时，只能写“实现了该链路”，不能写“达到某项精度”。
