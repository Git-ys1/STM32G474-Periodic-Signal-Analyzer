# 项目总背景、目的与当前状态

## 1. 项目是什么

本项目服务于 2026 年电赛 G 题“周期信号测量分析装置”。装置需要接收评测专家给出的周期电压信号，在 STM32G474VET6 上完成采集、分析和结果组织，再通过不小于 6 英寸的显示屏稳定展示时域波形、正频率轴频谱、峰峰值、真有效值、基频以及主要频谱分量的频率与峰值幅度。题目中的信号不是任意自然信号，而是由一个基波正弦和一个或两个谐波正弦组成的周期信号；各分量都在规定频率范围内，输入无直流偏置。项目的意义不只是“画出一条曲线”，而是把模拟前端、ADC、DSP、结果快照、界面协议和现场交互组成一条可重复验证的测量链。

用户是显示和融合侧负责人，不负责重新发明队友的整套 ADC/FFT 算法。队友负责 STM32 的 ADC 采集、FFT、频率与幅值估计、Vpp/RMS 等信号处理主体。用户负责淘晶驰 X2 7 英寸屏幕的 HMI 工程、单页 dashboard 布局、USART3 协议、曲线透传、参数文本、1T/3T 显示、不可触摸屏的实体 KEY1 替代操作，以及把队友输出整理成稳定的 `AnalyzerResult`。双方最终不是把两个 `main.c` 粘在一起，而是以队友工程为硬件与算法底座，把用户侧 `analyzer_bridge.c/.h` 和 `display.c/.h` 作为叠加模块接入。

## 2. 当前已经做到哪里

当前发布基线是Git标签`v2.1.0`，它以`v1.9.0 / 9b023b5`真实ADC融合版为
底座。权威工程位于：

```text
F:\Project\stm32G474VETx\TI\G_Periodic_Signal_Analyzer
\firmware
```

它已经完成以下融合：

- 队友最新 ADC1/PA0、TIM3 TRGO、DMA1 Channel 1、2048 点采样底座；
- CMSIS-DSP 2048 点 FFT、三峰提取、Vpp_Robust、RMS 和 Goertzel 源码；
- 第一次 FFT 后快照频谱结果，防止 `Vpp_R()` 内部第二次 FFT 覆盖全局变量；
- `AnalyzerBridge_PublishReal()` 将原始 `adc_b[2048]`、队友测量值和谱峰打包成统一快照；
- 基频附近相关搜索细化折叠频率，将完整 2048 点按相位折叠成 256 点周期波形；
- `Display_Task()` 把 256 点重采样成两条 794 点 HMI 曲线，显示 1T/3T、频谱线和六项文本；
- dashboard 初始化动态上报两条曲线的实际数字 ID，避免 HMI 改布局后硬编码失效；
- USART3 单字节中断接收和 ORE 恢复，避免 FFT 长任务期间漏掉按钮或页面帧；
- KEY1 PB8短按切换1T/3T，长按进入随机测试，且和HMI按钮共用同一命令入口；
  V2.2按不可触摸屏现场要求恢复了该映射；
- `addt → FE → 原始曲线数据 → FD` 可靠透传；
- ArmClang 的 `__ARM_use_no_argv` 启动修复，以及大型 `AnalyzerResult` 静态存储的栈溢出修复；
- 时域和频谱的淘晶驰横向写入方向补偿；
- 时域显示可选择无触发、上升过零、下降过零和正峰值相位锚，默认上升过零；
- 淘晶驰下拉框以`A5 02 07 mode 5A`同步最终触发模式；
- 两遍Huber折叠已通过PC端72组对照验证，并以默认关闭的
  `A5 02 08 enabled 5A`状态开关加入STM32；
- 当前V2.2工作树已使用三组真实`adc_b[2048]`验证“Huber + FFT已识别
  整数谐波投影”，并完成零警告构建、烧录和运行态冒烟，但尚未发布；
- PC 离线自定义周期波形实验室、相位覆盖扫描、低分母共振和频率误差敏感性验证。

该版本曾完成 Keil 0 error、0 warning 构建，使用 STM32CubeProgrammer 通过 SWD 写入并校验；ST-Link HOTPLUG 观察到结果序号持续递增，CFSR/HFSR 为零，说明 ADC、分析、桥接和显示任务没有立即 HardFault。这里的“能够稳定运行”只表示主链路在跑，不等于所有测量指标已满足题目。

## 3. 当前真正的开发阶段

当前已经离开“正弦动画和串口屏演示”阶段，进入真实 ADC 联调与算法责任审计阶段。下一步主线不是继续美化 UI，也不是再重构一次文件，而是基于同一稳定信号保存四份同步证据：

```text
信号源设定值
ADC引脚处示波器读数
同一帧adc_b[2048]原始数组
屏幕最终Upp/Urms/频率/频谱/波形
```

用户已经明确纠正：信号发生器与示波器的 Vpp 差值通常小于 5 mV，但示波器与屏幕显示经常相差超过 10 mV。因此不能再把幅值误差归因于“信号到 ADC 引脚前被放大了”，也不能凭单张截图下结论。正确的待查链路是 `PA0 → adc_b[] → 3.3/4096 换算 → VO[] → Vpp_Robust()/Vpp_R() → AnalyzerBridge → Display 文本`。显示层目前只做 V→mV 单位换算和定点字符串格式化，并不重新计算 Vpp；但 ADC 比例、实际 VDDA、采样相位、鲁棒峰值算法和桥接输入都需要实测。

另外仍有三项重要问题：纯正弦可能被队友FFT固定识别出第二峰；相位折叠波形
可能有毛刺或低相位覆盖失真；V2.2已把三组真实ADC中的模型外抖动压到
0.15 mV量级，但屏幕普通/增强Huber同信号A/B尚未验收。离线实验已经证明，
精确256 kHz与约1.024 MHz采样率形成
低分母关系时只有少量真实相位，增加槽数不能创造信息；谐波最小二乘拟合可能
比强行插值更可靠，但频率误差又会让表面覆盖率虚高，所以后续必须同时看覆盖率、
最大空洞、拟合残差和频率稳定性。

## 4. 不能再犯的恢复错误

任何新会话不得：

- 从 `test` 里的最初 `main.c` 或 `tjc_display_demo` 重新替换融合工程；
- 把 `teammate_adc_reference/newest/reallynewest!` 当作当前可直接烧录的成品；
- 恢复双页面 time/spectrum 方案；
- 把旧的 time=11、spectrum=1 写死到当前 dashboard；
- 删除 FE/FD 握手、UART 中断接收、栈保护或 no-argv 修复；
- 为了“代码短”再次改变已经验收的行为；
- 把测试模式预生成数据当作真实 ADC 算法验收；
- 用平滑或显示缩放掩盖测量误差；
- 未经同步数据对照就把毛刺、伪峰或 Vpp 偏差归到某一层。
