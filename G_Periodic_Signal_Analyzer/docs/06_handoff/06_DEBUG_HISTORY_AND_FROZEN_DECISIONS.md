# 调试历史、根因与冻结决策

## 1. 为什么必须保留故障史

本项目最昂贵的损失不是某一行代码写错，而是修复完成后没有把根因和版本边界冻结，下一次上下文压缩又从旧方案重做。下面每项都写明症状、根因、修复和禁止回退内容。新会话遇到相似现象时先查这里，再做最小实验，不能再大范围重构。

## 2. 时域曲线0x12而频谱正常

早期双页面模块化后，代码把 time 和 spectrum 错误共用曲线 ID 1。历史正常日志显示 `time.s0` 数字 ID 为 11，`spectrum.s0` 为 1，所以时域执行 `cle 1,0 / addt 1,0,674` 时屏幕返回：

```text
12 FF FF FF
```

含义是曲线 ID 或通道无效。把时域改回 11 后双页面恢复。但这只是旧版事实。后来 HMI 改为 dashboard 单页面，曲线改名 `s_time/s_spec`、宽度改为 794；为了彻底避免布局改动造成 ID 漂移，当前页面初始化动态发送两条实际 ID：

```text
A5 20 01 time_id spec_id 5A
```

冻结决策：当前单页版本绝不硬编码 11/1，也不共用一个固定 ID。遇到 0x12 首先检查 HMI 初始化事件是否发送、MCU 是否收到 6 字节帧、目标曲线是否在当前页面、通道是否为 0。

## 3. 页面只有按钮帧，没有曲线和文本

曾经 MCU 代码等待页面“ready”帧，而 HMI 后初始化事件仍使用旧格式；也发生过只看到模拟器返回 `A5 01 01 5A`、`A5 01 03 5A`，串口设备端完全没有 MCU 输出的情况。根因不是波形算法，而是 HMI 与 MCU 对页面初始化协议不同步，或者用户只在 HMI 模拟器内点击而物理串口未联机。修复是成对更新 HMI 与固件，确保 dashboard 后初始化发送完整 6 字节 ID 帧，并在 `Display_Init()` 后主动 `page dashboard` 触发握手。

冻结决策：修改协议必须同时检查 HMI 事件代码、固件解析器和实物串口。模拟器“返回数据”窗口是 HMI→MCU 的拟真输出，不等于真实 STM32 已经收到；“串口设备返回数据”或 ST-Link 状态才是 MCU 侧证据。

## 4. FE/FD与错误码混淆

正常曲线透传会出现：

```text
FE FF FF FF
FD FF FF FF
```

FE 表示屏幕准备接收 `addt` 原始数据，FD 表示透传结束。它们不是错误。`1A` 是变量名无效，曾因 C 代码使用 `t_mode/t_vpp` 等显示文字而不是 HMI 实际 objname 导致连续四次报错；`1C` 是赋值语法问题；`24` 常见于串口缓冲溢出。修复文本名称后，所有命令使用真实 objname 和完整 `.txt="..."`。

冻结决策：`TJC_SendCurveBlock()` 的 FE/FD 等待、超时和长度检查必须保留，不允许为了缩短代码直接发送 794 字节。错误码要按发送命令数量和时序对应，不可看到 FF 就统称通信失败。

## 5. 模块化后完全不显示与主栈溢出

把大结构体封装进函数后，曾在局部栈上创建包含 `float waveform_mv[256]` 的 `AnalyzerResult`，其大小超过 1 KB，而 Keil 主栈只有约 1 KB。随后 UART 句柄或返回地址被覆盖，表面症状是屏幕无输出、按钮无反应或在 HAL UART 内 BusFault。修复为桥接层和显示层的结果快照、排序数组、相位累加数组全部使用模块静态存储，主循环和绘图函数只传指针。

冻结决策：大型数组不放栈，不为追求“局部变量干净”恢复。新算法增加 2048 点浮点数组时必须先做 RAM/stack 审计。

## 6. 上电停在BKPT 0xAB

队友 Keil ArmClang 6.7 工程在独立运行时曾在进入 `main()` 前触发半主机 `BKPT 0xAB`，表现为固件像没启动。根因是 C 运行库试图获取 argc/argv。修复是在当前 `main.c` 保留：

```c
#if defined(__ARMCC_VERSION)
__attribute__((used)) int __ARM_use_no_argv;
#endif
```

冻结决策：升级队友底座时必须交叉检查该标记，不得因“看起来与业务无关”删除。若重新出现 BKPT，要先查启动库和半主机，不要先改屏幕。

## 7. FFT期间按钮失效和UART ORE

早期 HMI 字节只在主循环轮询。2048 点 FFT、排序和相关搜索占用时间较长，UART 接收寄存器来不及读取，产生 ORE 后接收永久停住，导致四个或六个按钮首次/偶发无反应。修复为 USART3 单字节中断接收：每收到一字节立即送入解析器并重新挂接；错误回调清 ORE、flush、丢弃残帧后继续。实际绘图仍在主循环，避免中断里阻塞发送。

冻结决策：保留 RX 中断和错误恢复；不能退回纯轮询，也不能把 `addt` 发送搬进中断。

## 8. 实体KEY1与HMI两套状态机冲突

商家发成不可触摸屏后，最初为PB8另写显示逻辑。短按/长按触发的画面会闪一下，
又被旧的自动刷新状态覆盖，表现为Upp从一值短暂变成另一值再恢复。根因是KEY
直接绘图，没有走原HMI命令状态机。修复为KEY只映射到已有接口：短按
`Display_TogglePeriods()`；长按在V1.9曾映射`Display_RequestRefresh()`，
V2.2按用户现场要求改为`Display_RequestTest()`；两者内部最终调用
`Display_ProcessButtonCommand()`。

冻结决策：实体按键和触摸/HMI必须共用一套命令入口。EXTI只记时刻，松开与
业务动作在主循环。当前V2.2长按是测试；真正冻结的是统一入口和中断边界，
不是某个历史按键动作。

## 9. 时域左右镜像和频谱边缘

淘晶驰曲线的数据写入方向与 PC 工作室图像预期相反。早期只对频谱做了反转，时域表现为相位 0 后本应上升却下降，即整个周期左右镜像。修复为时域发送缓冲也使用：

```text
destination[width - 1 - i] = mapped(source[i])
```

频谱 500 kHz 谐波曾贴在最右边，影响观看；当前 `DISPLAY_SPEC_X_MARGIN=32`，把 0～500 kHz 映射到左右留白后的有效区，再做淘晶驰方向补偿。

冻结决策：时域和频谱的方向补偿都保留；频谱边距不影响下方数值，只改善定性图可见性。任何重新映射都要用已知 100/250/500 kHz 谱线验收。

## 10. 波形重建与低相位覆盖

旧实现只截取第一个周期并拉伸，高频时每周期仅 2～10 个真实采样，复合波形严重失真。V1.9 改为用完整 2048 点相位折叠到 256 槽。离线 `phase_coverage` 和自定义波形实验室进一步证明：当 `f/Fs` 是低分母有理数时，真实相位数量被分母限制；精确 256 kHz 附近可能只有 4 个相位，64/128/256 槽都不能挽救，插值误差约 8 mV。谐波最小二乘在理想分量已知时可降至约 0.24 mV，但若频率估计偏差 100 Hz，覆盖率可能虚高而波形更差。

冻结决策：不能只按频率区间或硬覆盖率选择槽数。后续自适应策略必须同时考虑独立相位数、覆盖率、最大空洞、频率稳定性和模型残差；低可信场景可降槽、显示原始点、改采样率/双采样率，或在谱峰可信后做谐波最小二乘。

## 11. 文本数字为空

newlib-nano 未链接 `_printf_float` 时，`snprintf("%.1f")` 只输出前后文字而浮点数字段为空。修复是显示侧将值转为放大 10/100 倍的整数，以 `%lu` 拼接一位或两位小数。

冻结决策：除非明确调整 Keil 链接选项并评估代码体积，否则保持定点格式化。看到标签存在但数值为空，先查 printf 浮点支持，不要改 HMI 文本控件。

## 12. 发布与回滚原则

每个稳定阶段都要先保存 Git 提交和标签，再做下一项。出现回归时用 diff 找最小变化，不能把“最初能显示的 main.c”整文件覆盖融合工程。独立显示基线、队友原始快照和全量融合版都要保留各自用途；修复后必须同步更新 `CURRENT_STATUS`、故障文档和构建/烧录证据，避免下个会话只记住错误中间态。
