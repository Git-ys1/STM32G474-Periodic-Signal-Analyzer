# V2.1普通/Huber相位折叠状态开关

日期：2026-07-31
发布版本：`v2.1.0`
基线：`v2.0.0 / ff4982c`
工程：`projects/g474_full_integration_test`

## 1. 目标和默认行为

V2.1把已经通过PC人工毛刺验证的两遍Huber相位折叠加入STM32，作为可视化
对照手段。上电默认仍为V2.0.0普通折叠：

```text
false / val=0：普通相位折叠
true  / val=1：两遍Huber鲁棒相位折叠
```

两种模式只重建`AnalyzerResult.waveform_mv[256]`。队友测得的`Upp`、`Urms`、
基频、频谱分量和原始`adc_b[2048]`均不被修改，显示层也不从处理后波形反算
测量参数。

## 2. HMI到MCU协议

状态开关使用独立五字节帧：

```text
A5 02 08 enabled 5A
```

| 帧 | 含义 |
|---|---|
| `A5 02 08 00 5A` | 普通折叠 |
| `A5 02 08 01 5A` | Huber折叠 |

USART3中断只保存`enabled`和待处理标志；2048点残差、MAD和第二遍折叠均在
`Display_Task()`主循环上下文执行，避免把重计算放进UART中断。

## 3. 淘晶驰状态开关配置

X2系列支持官方“状态开关”控件。建议新增：

```text
objname = sw_huber
vscope  = 全局
val     = 0
txt     = 普通/Huber
dez     = 0
```

官方要求`txt`为空，或用斜杠分隔两个状态。弹起事件：

```text
printh A5 02 08
prints sw_huber.val,1
printh 5A
```

`dashboard`页面后初始化事件在曲线ID帧和触发模式帧之后增加：

```text
printh A5 02 08
prints sw_huber.val,1
printh 5A
```

`vscope=全局`用于在`page dashboard`重新加载后保留选择。状态开关不勾选
“发送键值”。官方资料：

- [淘晶驰状态开关控件](http://wiki2.tjc1688.com/widgets/Switch.html)
- [prints发送变量或常量](http://wiki2.tjc1688.com/commands/prints.html)

## 4. STM32算法

Huber模式先完整执行原普通折叠，再用普通256点周期波形在每个ADC样本相位处
进行周期线性预测：

```text
residual = centered_adc_mv - predicted_mv
residual_center = median(residual)
robust_sigma = 1.4826 × median(abs(residual - residual_center))
delta = max(1.345 × robust_sigma, 1.5 × ADC_LSB)
```

大残差样本使用：

```text
sample_weight = delta / abs(residual - residual_center)
```

第二遍仍折叠原始中心化ADC样本，将`sample_weight`乘入原左右相位槽权重。
随后继续使用普通链路的每槽加权平均、环形空槽线性补齐和去均值。没有加入
全局平滑、三次样条、PCHIP或Akima。

中位数使用2048点静态工作区和原地选择算法，避免`qsort`递归及额外副本。
桥接层还保存最近一帧真实ADC码，切换时可立即按当前最新一帧重建；测试模式
复用当前测试组，不因切换算法而随机换组。

## 5. 资源变化

V2.0.0发布构建：

```text
Code=64652, RO-data=59000, RW-data=52, ZI-data=50756
```

V2.1.0发布构建：

```text
Code=68532, RO-data=59000, RW-data=52, ZI-data=63068
```

变化：

```text
Code：+3880 bytes
ZI-data：+12312 bytes
```

新增ZI主要来自2048点浮点残差工作区（8192字节）、最近一帧真实ADC副本
（4096字节）和少量状态。所有大数组均为模块静态存储，未增加1 KB主栈压力。

本轮构建：

```text
Arm Compiler 6.7
0 Error(s), 0 Warning(s)
ADC.hex：358927 bytes
SHA-256：FA1CC4CCB29C1B29C0832A31970DCF5C91CCF823962DA71FF4A04902F8252600
```

STM32CubeProgrammer 2.22.0以SWD Under Reset、约950 kHz、目标电压3.19 V
完成下载、校验和复位，日志返回`Download verified successfully`。HOTPLUG
运行态冒烟结果：

```text
上电默认模式：0（普通）
调试标志模拟状态开关：0 → 1 → 0
分析序号：0x100 → 0x236 → 0x2A9
CFSR：0x00000000
HFSR：0x00000000
```

这证明Huber主循环能够进入、持续发布结果并恢复普通模式，且未触发可配置Fault
或HardFault。真实HMI帧和实际曲线效果仍需在加入`sw_huber`后验收。

## 6. 建议验证

1. 状态开关保持`普通`，确认曲线与V2.0.0一致；
2. 在稳定真实信号下切到`Huber`，确认只重画时域，六项文本和频谱不变；
3. 在测试模式同一T编号的3秒刷新窗口内快速往返切换，确认不会更换测试组；
4. 对真实毛刺保存普通/Huber截图和对应`adc_b[2048]`；
5. T103/T108等低覆盖场景不要求改善，需保留退化证据；
6. 连续异常可能共同污染第一遍预测，不能把Huber当作采集质量检查的替代。

PC人工污染结果显示，中高覆盖孤立异常的显示RMSE中位改善约55%，但精确
256 kHz低覆盖案例可能退化。上板开关的意义是取得真实ADC证据，不代表Huber
已经成为正式默认算法。
