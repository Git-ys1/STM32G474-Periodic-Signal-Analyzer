# 真实 ADC 首次联调问题审计

日期：2026-07-31
对象：`firmware`
性质：责任边界与根因审计；本轮未修改固件

> 后续状态：V2.0.0已经针对本文识别的帧间水平漂移加入显示层相位锚并完成
> 构建、烧录；本文其余Vpp、伪峰和毛刺审计结论仍有效，真实连续帧验收尚待补齐。

## 1. 本轮结论

首次真实电路联调暴露的四个问题不能全部归到显示模块：

| 现象 | 当前判断 | 主要责任层 |
|---|---|---|
| 示波器与信号源 Vpp 相差不到 5 mV，但屏幕与示波器经常相差超过 10 mV | 误差发生在 ADC 采样、码值换算或 `Vpp_Robust()`之后；显示层只透传结果 | ADC 测量链 + 队友 Vpp 算法 |
| 纯正弦输入却显示第二、第三频率分量 | 单张示波器图不足以证明模拟链路已产生相应谐波；队友 FFT 当前至少固定输出两个峰 | 信号分析算法优先排查，硬件待同步频谱验证 |
| 时域曲线有毛刺、不够平滑 | 可能来自原始 ADC 噪声，也可能由相位折叠的普通平均放大；现有截图不能单独定责 | ADC 原始数据 + 桥接重建 |
| 每约 3 秒刷新后波形横向移动 | 每帧 ADC 起点相位任意，折叠固定从 `phase_cycles=0` 开始，没有相位锚定 | `analyzer_bridge` |

最重要的责任边界是：

> 当前显示模块没有重新计算或修改 Upp、Urms 和频谱幅值；它只是把 `AnalyzerResult` 中的数值格式化并发送到屏幕。

因此，不能用修改显示缩放的方式修正测量误差；但 ADC 码值换算和
`Vpp_Robust()`都在显示之前，仍属于当前固件需要联合审计的范围。

## 2. 三层实测对照

### 2.1 经多次实测确认的关系

| 位置 | 观测结果 |
|---|---:|
| 信号发生器与 ADC 引脚示波器 | Vpp 差值不到 5 mV |
| ADC 引脚示波器与屏幕 | Vpp 经常相差超过 10 mV |
| 屏幕第 1 帧 | Upp 172.0 mV，Urms 41.01 mV |
| 屏幕第 2 帧 | Upp 177.6 mV，Urms 40.84 mV |
| 屏幕第 3 帧 | Upp 174.5 mV，Urms 40.37 mV |

上表后三行只是三张屏幕截图中的显示值，不是与示波器同一时刻锁存的配对数据，
不能据此反推模拟前端增益。单张截图只能说明当时状态，不能替代多次配对测量。

正确结论是：信号到达 ADC 引脚前的幅值基本正常，明显 Vpp 偏差出现在
`PA0 → adc_b[] → VO[] → Vpp_Robust() → AnalyzerResult`这条测量链中。

### 2.2 频谱与 RMS 的相互印证

屏幕三帧中，基波约 `48.7～49.1 mVpk`，第二分量约 `24.5～24.6 mVpk`。若把两者视为互不相关的正弦分量，其理论真有效值约为：

```text
sqrt((49.1^2 + 24.5^2) / 2) = 38.8 mV
```

与显示的 `40.37～41.01 mV` 较接近。

这只能说明屏幕上的 FFT 幅值与屏幕上的 RMS 在数学上大体自洽，不能证明
200 kHz 分量在模拟电路中真实存在。若 FFT 把泄漏或噪声误选为第二峰，同样会得到
“内部自洽但物理错误”的一组数。必须用示波器 FFT 或导出的原始 ADC 数组同步验证。

## 3. Upp 链路审计

当前真实链路为：

```text
adc_b[2048]
→ adc_code × 3.3 / 4096
→ VO[2048]
→ Vpp_Robust()
→ AnalyzerBridge_PublishReal(vpp)
→ vpp × 1000
→ AnalyzerResult.vpp_mv
→ Display_UpdateResultTexts()
→ t_vpp
```

代码证据：

- `Core/Src/main.c`：ADC 码转换和 `Vpp_Robust()` 调用；
- `Core/Src/analyzer_bridge.c`：只执行 `vpp_v * 1000.0f` 的 V→mV 单位换算；
- `Core/Src/display.c`：只把 `result->vpp_mv` 格式化为一位小数。

`Vpp_Robust()`对 2048 点排序，分别平均低端和高端各 10 个点后相减。它可以降低单个尖峰对峰峰值的影响，但当前存在以下误差入口：

- 固件固定用 `3.3 / 4096`，实际 VDDA 尚未代入；
- ADC 增益、偏置和参考电压误差；
- `Vpp_Robust()`取“最高 10 点均值 - 最低 10 点均值”，并不等于连续波形真正峰峰值；
- 采样相位未必恰好命中峰顶，低相位覆盖频点会系统性低估；
- ADC 输入驱动不充分、采样保持充电误差和数字噪声；
- 示波器与屏幕没有锁存在同一采样帧，瞬态噪声会增加比较散差。

已经确认 `main.c`调用了 `HAL_ADCEx_Calibration_Start()`，所以“完全没有执行 ADC
自校准”不是当前根因。2 倍过采样并右移 1 位仍维持 12 位码宽，`4096`与`4095`
的差别也远不足以解释超过 10 mV 的误差。

当前 Upp 排查应直接记录同一帧的：

```text
adc_b[]原始最小/最大码
排序后最高/最低10点均值
Vpp_Robust()结果
实测VDDA
示波器同位置Vpp
```

再用 PC 离线同时计算 `max-min`、分位数、正弦/谐波最小二乘 Upp，才能确定主要误差是
电压比例还是峰值统计方法。

## 4. “莫名谐波”审计

队友 `fft()` 的现有逻辑是：

1. 2048 点复数 FFT；
2. 找到最大峰，并把峰值左右各 8 个频点的平方和换算成幅值；
3. 清零该频带，再找第二峰；
4. 再清零，再找第三峰；
5. 只有第三峰 `VC < 0.004 V` 时才把分量数设为 2，否则设为 3。

因此当前算法具有两个重要行为：

- 无论输入是否为纯正弦，都会至少发布两个峰；
- 第二大剩余峰没有绝对阈值、相对阈值、噪声底判断或谐波整数倍验证。

`AnalyzerBridge_PublishReal()`只是按队友的 `flag=2/3`复制这些峰并排序，显示层再把它们标为“基波、谐波1、谐波2”。桥接层和显示层没有自行制造新的频率分量。

建议队友侧下一步把“谱峰”和“谐波”分开：

1. FFT 前加入 Hann 窗，并按相干增益修正幅值；
2. 对每个候选峰同时使用绝对阈值、相对基波阈值和局部噪声底阈值；
3. 只有频率接近 `n × f1` 时才标为第 `n` 次谐波；
4. 不满足整数倍关系的峰显示为杂散或不显示；
5. 第二峰也必须允许不存在，不能固定发布；
6. 对峰位做抛物线插值或使用已保留的 Goertzel 做精测，但须先统一标定口径。

## 5. 时域毛刺审计

### 5.1 现有重建方法

`AnalyzerBridge_BuildRealWaveform()`不是直接截取一个周期，而是：

```text
2048 个 ADC 点去均值
→ 在 FFT 基频附近 ±500 Hz、10 Hz 步进相关搜索
→ 按相位折叠到 256 个槽
→ 每个样点按线性权重分配给相邻两个槽
→ 有覆盖槽做加权平均
→ 空槽做环形线性插值
→ 再去均值
```

随后 `Display_DrawTimeResult()`把 256 槽周期波形用线性插值扩展到 794 个屏幕横向点。

### 5.2 毛刺为什么仍然存在

当前毛刺可能来自两部分，必须用原始 ADC 数组区分：

1. **ADC 原始采样中的噪声或异常点。** 单张示波器截图不足以量化其贡献，不能先认定为模拟前端毛刺。
2. **相位槽只做普通平均。** 频率估计误差、采样时钟抖动、帧内幅值变化和异常样点会让同一相位槽内的样本互相不一致；普通平均不能抵抗离群点。

256→794 的线性插值只是在相邻槽之间连线，不会创造新的真实信息，也不会自动消除局部跳变。直接改成三次样条还可能在尖峰附近过冲，不能作为第一修复手段。

### 5.3 推荐的软件优化顺序

1. 在每个相位槽保存离散程度，例如方差、平均绝对偏差或 MAD；
2. 对槽内样点使用截尾均值、Huber 均值或中值，抑制少量毛刺；
3. 折叠后只增加很轻的环形 3/5 点平滑，且保留原始波形用于 Upp、RMS 和 FFT；
4. 输出覆盖率、最大空洞和拟合残差，低可信时不要把稀疏点伪装成高分辨率曲线；
5. 对题目规定的“基波 + 最多两个谐波”，可进一步评估正弦/余弦最小二乘拟合，用检测到的频率同时估计幅值和相位后重建；但必须先解决伪峰判定，不能拿错误分量拟合。

平滑只作用于**显示波形副本**，不得改动队友用于 Upp、Urms、FFT 的原始 `VO[2048]`。

## 6. 每 3 秒波形横移的根因

`DISPLAY_REFRESH_INTERVAL_MS=3000`只决定何时重绘，不决定采样帧从信号的哪个相位开始。

外部信号源与 TIM3/ADC 时钟不同步，每个 `adc_b[2048]`缓冲区的首点相位都会变化。当前折叠函数每帧都使用：

```c
float phase_cycles = 0.0f;
```

这等价于把本帧 `adc_b[0]`强行定义为显示周期的相位零点。因此每刷新一帧，整个周期会发生环形平移。把 3 秒改成其他固定时间只能偶然减小移动，不能从根本上解决。

推荐修复：

1. 用基波的正交相关或 Goertzel 复结果求出基波相位；
2. 对折叠后的 256 点数组做环形旋转；
3. 固定“基波正向过零点”为数组第 0 点；
4. 必要时再用上一帧与当前帧的环形互相关做小范围微调和迟滞。

这个修复只改变周期从哪里开始显示，不改变 Upp、Urms、频率、频谱幅值和复合波形内部相对相位。

## 7. 硬件排查边界

当前仓库和资料目录只确认 ADC 接口为 `ADC1 PA0/IN1`，没有找到实际模拟前端原理图、BOM 或运放/滤波器具体型号。因此本轮不能负责任地指定“更换某型号运放”。

多次实测已经确认信号源与 ADC 引脚示波器的 Vpp 差值不到 5 mV。硬件排查的重点转为 ADC 输入驱动、VDDA、偏置和噪声，而不是先假设外部放大倍数错误。

在取得原理图或实物器件丝印前，先按下列顺序分段测量：

```text
信号源 BNC 输出
→ 50 Ω终端/输入保护之后
→ 每一级放大与滤波之后
→ 偏置与 ADC 驱动之后
→ PA0
```

每一级同时记录：

- 100 kHz 时的 Vpp、偏置和波形失真；
- 10～500 kHz 幅频响应；
- 是否出现削顶、振铃或自激；
- 示波器和信号源的 50 Ω/High-Z 设置；
- PA0 前的串联电阻、并联电容和驱动源阻抗；
- 3.3 V 模拟电源、参考电压和地噪声。

当前固定使用 `3.3 / 4096`换算 ADC 电压，还应实测 VDDA，并进行零点和增益两点标定。

## 8. 下一轮最小验收矩阵

下一轮不要先堆算法。每个测试点应尽量在同一稳定状态下保留四份证据：

```text
信号源设置
ADC 引脚示波器截图
原始 adc_b[2048]
屏幕最终结果
```

建议测试：

| 项目 | 测试点 |
|---|---|
| 频率 | 10、100、200、250、400、500 kHz |
| 输入幅度 | 50、100、250 mVpp |
| 信号 | 纯正弦；已知基波+谐波组合 |
| 显示 | 连续至少 10 帧，记录帧间相位平移 |

每点计算：

- PA0 实测 Upp 与屏幕 Upp 的误差；
- PA0 实测 RMS 与屏幕 RMS 的误差；
- 基频误差；
- 第二/第三峰与噪声底、基波的幅值比；
- 256 相位槽覆盖率、最大空洞、槽内离散程度；
- 相邻两帧最佳环形位移量。

## 9. 修改优先级

### P0：先做实测，不改算法

- 继续确认信号源和示波器负载口径；
- 实测 VDDA，并核对 `3.3 / 4096`换算误差；
- 取得模拟前端原理图、BOM或清晰器件照片；
- 导出一帧原始 `adc_b[2048]`，同时保存同一状态下的示波器 Vpp；
- 对同一数组比较 `max-min`、10 点极值均值、分位数和模型拟合 Vpp。

### P1：低风险软件修复

- 给时域波形增加基波相位锚定，消除帧间横移；
- 给第二、第三谱峰增加存在性判定；
- 增加相位槽质量指标和离群点抑制。

### P2：在离线数据上比较后再上板

- Hann 窗 + 幅值校准；
- Goertzel/最小二乘幅相精测；
- 环形轻量平滑；
- 低覆盖场景的降槽、双采样率或模型重建。

## 10. 冻结说明

本审计只建立问题责任边界和下一轮实验顺序，没有修改：

- 队友 ADC/FFT/Vpp/RMS；
- `analyzer_bridge`相位折叠；
- `display`绘图与 3 秒刷新；
- Keil、CubeMX 或 HMI 工程。

在取得原始 ADC 数组前，不应直接提交“平滑曲线”或“修正幅值”的固件补丁，否则可能把 ADC 测量误差或重建误差掩盖成好看的图形。
