# 淘晶驰HMI通信协议

更新时间：2026-07-31
适用版本：V2.0触发相位锚dashboard单页面

## 串口参数

```text
USART3
PC10 = TX
PC11 = RX
115200 bit/s
8N1
```

普通淘晶驰字符串指令由MCU自动追加：

```text
FF FF FF
```

## HMI到MCU的自定义帧

### dashboard初始化帧

```text
A5 20 01 time_id spec_id 5A
```

共6字节。`time_id`与`spec_id`分别是当前HMI工程中`s_time`和`s_spec`的实际数字ID。
页面随后再发送`A5 02 07 mode 5A`，同步全局触发下拉框的当前选择。两者是两条
独立完整帧，不能拼成一条。

MCU收到并校验完整帧后：

1. 保存两个曲线ID；
2. 标记dashboard有效；
3. 若当前处于真实或测试自动刷新状态，执行整页绘制；
4. 若当前处于停止状态，只完成握手，保持页面原状。

### dashboard按钮帧

| 帧 | 含义 |
|---|---|
| `A5 01 01 5A` | 显示1个完整周期 |
| `A5 01 02 5A` | 重新加载dashboard并执行完整刷新 |
| `A5 01 03 5A` | 显示3个完整周期 |
| `A5 01 04 5A` | 启动随机测试，每3秒自动切换一组 |
| `A5 01 05 5A` | 单次清除两条曲线和六项参数 |
| `A5 01 06 5A` | 停止后续绘制，保留当前画面 |

上电默认停止。只有刷新或测试按钮能启动自动绘制；1T/3T只修改周期，
停止状态下不会自行恢复绘画。

测试按钮立即生成一组一致的`AnalyzerResult`并整页显示，之后每3秒重新随机一组。
它不伪造ADC采样，也不调用显示侧DFT。

刷新按钮取消测试覆盖、进入真实结果自动刷新，并恢复首次页面命令丢失。MCU收到后：

1. 选择桥接层的最新真实结果；
2. 发送`page dashboard`；
3. 等待页面重新上报两个真实曲线ID；
4. 立即完整显示一次，之后每3秒重绘最新真实结果。

清除按钮不改变运行状态：运行中清除后形成约3秒空白期，下一周期重新显示；
停止中清除后保持永久空白，直到刷新或测试。停止按钮不清屏，只冻结当前画面。

### V2.0时域触发选择

触发方式使用下拉框的`val`属性发送当前选中单元格ID，不再把四个选项伪装成
四条按钮命令。统一帧格式为：

```text
A5 02 07 mode 5A
```

其中`0x02`表示带1字节参数的控件帧，`0x07`表示触发方式，`mode`映射如下：

| `mode` | 完整帧 | 触发方式 |
|---:|---|---|
| `0` | `A5 02 07 00 5A` | 无触发 |
| `1` | `A5 02 07 01 5A` | 上升过零（默认） |
| `2` | `A5 02 07 02 5A` | 下降过零 |
| `3` | `A5 02 07 03 5A` | 正峰值 |

下拉框对象以`cb0`为例，在弹起事件中写：

```text
if(cb0.down==0)
{
  printh A5 02 07
  prints cb0.val,1
  printh 5A
}
```

`path`中的选项顺序必须与`mode=0~3`完全一致。下拉框直接发送最终模式，不需要
在屏幕侧维护“按一次循环到下一项”的隐含状态。触发只改变256槽周期波形在屏幕
上的循环起点：

- 无触发：保持旧行为，可用于对比原始帧间相位漂移；
- 上升/下降过零：以主正峰为参照选择相邻的稳定过零点，并做亚槽线性插值；
- 正峰值：以一个周期的主正峰为起点，并做三点抛物线亚槽细化。

触发模式不修改原始ADC、FFT、Upp、Urms、频率和频谱结果。运行状态下切换模式只
立即重绘时域曲线；停止状态下只保存选择，直到下一次刷新或测试。固件上电默认
使用上升过零触发，用来消除每帧DMA起点相位不同造成的水平漂移。

`cb0.vscope`应设为全局，默认`val=1`。这样刷新命令重新加载`dashboard`时，
下拉框不会悄悄恢复为其他视觉状态；页面后初始化事件在曲线ID帧之后再发送一次
当前`cb0.val`，保证屏幕与MCU状态一致。固件若已等待整页重绘，这条同步帧不会
把待处理动作降级成只画时域曲线。

详细状态转换见[V1.5自动刷新状态机](V1.5_AUTO_REFRESH_STATE_MACHINE.md)。

刷新按钮的页面恢复步骤仍为：

1. 发送`page dashboard`；
2. 等待页面后初始化事件重新发送6字节初始化帧和5字节触发同步帧；
3. 重新保存两个真实曲线ID与当前触发方式；
4. 完整刷新时域、频谱和六项测量文本。

## 曲线透传

每条曲线保持原有可靠握手：

```text
MCU发送 cle id,0
MCU发送 addt id,0,794
HMI返回 FE FF FF FF
MCU发送794字节曲线数据
HMI返回 FD FF FF FF
```

- `FE`：透传就绪；
- `FD`：透传完成。

程序同时记录空闲阶段收到的四字节状态帧，并在同步等待透传时将非FE/FD状态帧作为错误返回。

## 当前接收实现

V1.4不再只依赖主循环轮询读取HMI字节。USART3采用单字节中断接收：

1. `HAL_UART_RxCpltCallback()`把字节送入协议解析器；
2. 回调末尾立即重新启动下一字节接收；
3. `HAL_UART_ErrorCallback()`清除ORE、flush接收寄存器并重新启动；
4. 页面与按钮事件仅设置待处理状态，实际曲线传输仍在主循环执行。

这样可以避免2048点FFT期间主循环长时间不读UART导致ORE，同时避免在中断中执行
阻塞式`addt`发送。

禁止出现：

```text
12 FF FF FF
1A FF FF FF
1C FF FF FF
24 FF FF FF
```

常见含义：

- `0x12`：曲线ID或通道无效；
- `0x1A`：控件或变量名称无效；
- `0x1C`：文本赋值语法错误；
- `0x24`：串口缓冲区溢出。

## MCU到HMI的文本命令

六项结果均使用objname和完整字符串，例如：

```text
t_vpp.txt="Upp: 200.0 mV"
t_rms.txt="Urms: 70.71 mV"
t_freq.txt="f1: 100.0 kHz"
t_c1.txt="基波: 100.0 kHz / 100.0 mVpk"
t_c2.txt="谐波1: --.- kHz / --.- mVpk"
t_c3.txt="谐波2: --.- kHz / --.- mVpk"
```

每条命令末尾均追加三个`0xFF`。HMI工程与C源码必须统一使用UTF-8。

原生ADC测试模式下，`t_c3`末尾追加`[T1]`～`[T9]`，用于辨认当前测试向量；真实ADC模式不追加编号。该编号只改善测试可观测性，不参与测量和绘图。

当前STM32工程使用`newlib-nano`且没有链接`_printf_float`。因此文本格式化不得直接使用`%.1f`、`%.2f`，否则屏幕只会显示前缀和单位，浮点数字段为空。显示代码先将测量值四舍五入为定点整数，再通过`%lu`生成小数字符串。

## 不可触摸屏的KEY1控制

不可触摸实物使用最小系统板KEY1（PB8/BOOT0）保留原映射：

| KEY1操作 | 等效显示动作 |
|---|---|
| 短按后松开 | 在1T和3T之间切换 |
| 长按至少1秒后松开 | 执行原`A5 01 02 5A`，恢复真实ADC自动刷新 |

PB8上升沿中断只记录按下时刻，松开检测和显示动作均由主循环完成。实体按键与
HMI按钮共用同一个按钮命令处理函数：短按使用原1T/3T命令，长按使用原刷新命令；
不会建立第二套显示动作。

历史V1.4.1曾将长按映射为测试命令；V1.9.0已经改为
`Display_RequestRefresh()`。当前行为以
`projects/g474_full_integration_test/Core/Src/main.c`为准。

实现细节见[KEY1实体按键控制](KEY1_PHYSICAL_CONTROL.md)。
