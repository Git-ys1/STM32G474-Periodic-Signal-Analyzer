# 淘晶驰HMI通信协议

更新时间：2026-07-30  
适用版本：V1.4全量融合dashboard单页面

## 串口参数

```text
USART3
PC10 = TX
PC11 = RX
115200 bit/s
8N1
```

普通淘晶驰字符串指令由MCU自动追加：

```text
FF FF FF
```

## HMI到MCU的自定义帧

### dashboard初始化帧

```text
A5 20 01 time_id spec_id 5A
```

共6字节。`time_id`与`spec_id`分别是当前HMI工程中`s_time`和`s_spec`的实际数字ID。

MCU收到并校验完整帧后：

1. 保存两个曲线ID；
2. 标记dashboard有效；
3. 绘制当前1T或3T时域曲线；
4. 绘制频谱；
5. 更新六项测量文本。

### dashboard按钮帧

| 帧 | 含义 |
|---|---|
| `A5 01 01 5A` | 显示1个完整周期 |
| `A5 01 02 5A` | 重新加载dashboard并执行完整刷新 |
| `A5 01 03 5A` | 显示3个完整周期 |
| `A5 01 04 5A` | 随机切换一组一致的融合测试结果 |

1T/3T按钮只刷新`s_time`，不重复计算或发送`s_spec`。

测试按钮在分析结果层更新`AnalyzerResult`，随后重绘时域、频谱和文本。它不伪造
ADC采样，也不调用显示侧DFT。

刷新按钮用于恢复“MCU先启动、HMI模拟器后联机”导致的首次页面命令丢失。MCU收到刷新帧后：

1. 发送`page dashboard`；
2. 等待页面后初始化事件重新发送6字节初始化帧；
3. 重新保存两个真实曲线ID；
4. 完整刷新时域、频谱和六项测量文本。

## 曲线透传

每条曲线保持原有可靠握手：

```text
MCU发送 cle id,0
MCU发送 addt id,0,794
HMI返回 FE FF FF FF
MCU发送794字节曲线数据
HMI返回 FD FF FF FF
```

- `FE`：透传就绪；
- `FD`：透传完成。

程序同时记录空闲阶段收到的四字节状态帧，并在同步等待透传时将非FE/FD状态帧作为错误返回。

## 当前接收实现

V1.4不再只依赖主循环轮询读取HMI字节。USART3采用单字节中断接收：

1. `HAL_UART_RxCpltCallback()`把字节送入协议解析器；
2. 回调末尾立即重新启动下一字节接收；
3. `HAL_UART_ErrorCallback()`清除ORE、flush接收寄存器并重新启动；
4. 页面与按钮事件仅设置待处理状态，实际曲线传输仍在主循环执行。

这样可以避免2048点FFT期间主循环长时间不读UART导致ORE，同时避免在中断中执行
阻塞式`addt`发送。

禁止出现：

```text
12 FF FF FF
1A FF FF FF
1C FF FF FF
24 FF FF FF
```

常见含义：

- `0x12`：曲线ID或通道无效；
- `0x1A`：控件或变量名称无效；
- `0x1C`：文本赋值语法错误；
- `0x24`：串口缓冲区溢出。

## MCU到HMI的文本命令

六项结果均使用objname和完整字符串，例如：

```text
t_vpp.txt="Upp: 200.0 mV"
t_rms.txt="Urms: 70.71 mV"
t_freq.txt="f1: 100.0 kHz"
t_c1.txt="基波: 100.0 kHz / 100.0 mVpk"
t_c2.txt="谐波1: --.- kHz / --.- mVpk"
t_c3.txt="谐波2: --.- kHz / --.- mVpk"
```

每条命令末尾均追加三个`0xFF`。HMI工程与C源码必须统一使用UTF-8。

当前STM32工程使用`newlib-nano`且没有链接`_printf_float`。因此文本格式化不得直接使用`%.1f`、`%.2f`，否则屏幕只会显示前缀和单位，浮点数字段为空。显示代码先将测量值四舍五入为定点整数，再通过`%lu`生成小数字符串。

## 不可触摸屏的KEY1控制

不可触摸实物使用最小系统板KEY1（PB8/BOOT0）代替1T、3T和刷新触摸按钮：

| KEY1操作 | 等效显示动作 |
|---|---|
| 短按后松开 | 在1T和3T之间切换 |
| 长按至少1秒后松开 | 执行原`A5 01 04 5A`测试按钮命令 |

PB8上升沿中断只记录按下时刻，松开检测和显示动作均由主循环完成。实体按键与
HMI按钮共用同一个按钮命令处理函数：短按使用原1T/3T命令，长按使用原测试命令；
不会建立第二套显示动作。

实现细节见[KEY1实体按键控制](KEY1_PHYSICAL_CONTROL.md)。
